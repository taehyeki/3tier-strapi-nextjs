`notes/study-notes.html` 에 섹션 하나를 추가한다 (파일이 없으면 기존 스타일의 새 HTML로 만든다).
이 노트는 git 제외·비공개이며, 담당자가 **이해하고 공부하고 남에게 설명할 수 있을 만큼** 자세히 쓴다.

각 섹션 구성 (한국어):

1. **한 줄 요약** — 무엇을 했나
2. **만든/바꾼 것** — 파일 경로와 각 파일의 역할
3. **왜 했나** — 이게 없으면 무슨 문제가 생기나
4. **어떻게 동작하나** — 흐름을 단계로. 필요하면 인라인 SVG 도식
5. **대안과 트레이드오프** — 표: 선택지 / 장점 / 단점 / 이번에 고르지 않은 이유
6. **회사 환경으로 옮길 때** — 달라지는 점 (없으면 "없음")
7. **용어** — 처음 나온 용어 짧은 정의
8. **확인해 볼 것** — 담당자가 직접 쳐 볼 명령이나 볼 화면

마지막으로 `.claude/context/status.md` 도 갱신한다: 장 상태 표, 확정 설계에 새로 정한 것, "다음에 반영할 사실"에 새로 검증한 것.

규칙:
- 추측을 사실처럼 쓰지 않는다. 공식 문서로 확인한 내용이면 출처 링크를 단다.
- 코드는 핵심 부분만 발췌한다.
- 섹션 맨 위에 날짜와 단계 번호를 단다.
