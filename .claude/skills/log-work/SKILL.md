`notes/study-notes.html` 은 git 제외·비공개이며, **담당자가 공부하는 교재**다. 작업 일지가 아니다.
담당자가 원리를 이해하고, 남에게 설명하고, 다른 프로젝트에서 스스로 설정할 수 있을 만큼 쓴다.

노트는 두 파트로 나뉜다.

## 1부: 주제별 학습 (중심)

새로운 개념·도구가 등장하면 주제 섹션을 추가하거나 기존 주제에 보강한다 (예: CI와 GitHub Actions, git hook과 lefthook,
Docker 이미지, 공급망 보안, 시크릿 관리, IaC/CDK, OIDC…). 각 주제 구성:

1. **한 줄로** — 이게 무엇이고 무엇을 위해 있나
2. **없으면 무슨 일이 생기나** — 필요성. 실제 사고 사례가 있으면 출처와 함께
3. **원리** — 어디서(내 PC / GitHub 러너 / 컨테이너 / AWS) 무엇이 어떤 순서로 실행되나. 인라인 SVG 도식 권장
4. **남이 만든 도구·액션이면** — 누가 만들었고, 무엇을 제공하고, 내부에서 무엇을 하는가 (`uses:` 하면 실제로 무슨 일이 일어나나 등)
5. **이 저장소의 설정 한 줄씩** — 실제 파일을 발췌하고 항목마다: 의미 / 왜 이 값인가 / 빼면 어떻게 되나
6. **무엇을 감지·예방하나, 무엇은 못 막나** — 한계와 다른 방어선과의 관계
7. **대안 비교** — 표: 선택지 / 장점 / 단점 / 고르지 않은 이유
8. **직접 해 보기** — 담당자가 손으로 쳐 볼 실습 (일부러 실패시켜 보기 포함)
9. **용어**

## 2부: 작업 기록 (짧게)

날짜·단계, 한 일, 바꾼 파일, 발견한 문제와 해결. 원리 설명은 1부 주제로 링크한다.

마지막으로 `.claude/context/status.md` 를 갱신한다: 장 상태 표, 확정 설계, "다음에 반영할 사실".

규칙:
- 추측을 사실처럼 쓰지 않는다. 공식 문서(Context7 또는 공식 사이트)로 확인하고 출처 링크를 단다.
- 노트에 쓴 것을 대화에서의 설명으로 대신하지 않는다. 대화에서도 핵심을 설명하고, 노트는 복습·심화용이다.
