CHAPTER 07

변경을 운영까지: 작은 기능 하나를 끝까지 보내기

지금까지 만든 흐름을 처음부터 끝까지 한 번 돌려 봅니다. 로컬에서 작은 기능을 추가하고 PR을 머지하면, 나머지는 자동으로 운영에 반영됩니다.

추가 메뉴에 "売り切れ(품절)" 표시를 추가하고, 로컬 → PR → 머지 → 자동 배포 → 운영 관리자 화면에서 켜기까지 마친다.

1. 무엇을 바꾸나

직원이 관리자 화면에서 "품절"을 켜면, 사이트의 추가 메뉴가 흐려지고 "売り切れ"가 붙게 합니다.

작은 변경이지만 3층이 모두 등장합니다.

바뀌는 것층누가 바꾸나운영에 가는 방법
스키마: Extra에 soldOut(켜기/끄기) 필드백엔드로컬 관리자 화면 → Strapi가 파일로 저장PR → 머지 → 자동 배포
타입: 화면 코드가 soldOut을 안다프론트자동 생성
화면: 품절이면 흐리게 + "売り切れ"프론트사람이 코드로
데이터: "チャーシュー 는 품절"DB운영 관리자 화면배포되지 않음. 운영에서 직접

2. 흐름

① 필드 추가로컬 관리자 화면02장
→
② 화면 수정타입은 자동04장
→
③ 로컬 확인켜 보고 새로고침03·04장
→
④ PR → 머지CI 통과05장
→
⑤ 자동 배포약 10분06장
→
⑥ 운영에서 켜기운영 관리자 화면03장

3. 로컬: 필드 추가 백엔드

실행 위치: 저장소 루트

git switch -c feat/extra-sold-out
pnpm dev:db
pnpm dev:cms

Content-Type Builder → Extra → Add another field → Boolean. 이름은 soldOut, ADVANCED SETTINGS의 Default value는 false. Finish → Save.

Strapi가 저장한 설계도 보기 생략 가능

apps/cms/src/api/extra/content-types/extra/schema.json

"soldOut": {
  "type": "boolean",
  "default": false
}
로컬 Strapi를 켠 채로 브랜치를 바꾸지 마세요. 개발 모드의 Strapi는 파일이 바뀌면 다시 시작하면서 DB를 그 스키마에 맞춥니다. 필드가 없는 브랜치로 바꾸면 그 열을 지워서 입력해 둔 값이 사라집니다(이 자료를 만들 때 실제로 겪음). 브랜치를 바꾸기 전에 Strapi를 멈춥니다.

4. 화면 수정 프론트

화면 코드가 새 필드를 알도록 타입을 다시 만듭니다. pnpm gen:types를 실행합니다(DB 실행 중). 이 저장소처럼 lefthook에 gen-types를 넣어 두면, 잊어도 커밋할 때 자동으로 만들어집니다(이 장을 하면서 추가한 것, 9절). 그다음 추가 메뉴 부분을 고칩니다. 아래는 디자인을 뺀 요약이고, 실제 파일은 apps/web/src/app/page.tsx입니다.

{extras.map((extra) => (
  <li>
    <div className={extra.soldOut ? "흐리게" : undefined}>   // 품절이면 사진을 흐리게
      <Photo media={extra.photo} />
    </div>
    {extra.soldOut && <span>売り切れ</span>}              // 품절일 때만 표시
    <p>{extra.name} +{yen(extra.price)}</p>
  </li>
))}

데이터를 가져오는 코드는 고치지 않습니다. 추가 메뉴는 이미 모든 글자·숫자 필드를 받아 오고 있어서 새 필드도 그대로 들어옵니다.

생성된 타입이 boolean | null인 이유 생략 가능

필드를 추가하기 전에 만든 데이터는 값이 비어 있습니다(null). 기본값 false는 새로 만드는 데이터에만 들어갑니다. 화면에서는 null을 "품절 아님"으로 다룹니다. 타입을 다시 만들지 않은 채 extra.soldOut을 쓰면 타입 검사가 실패하므로, 잊어도 PR의 CI가 막아 줍니다.

5. 로컬에서 확인

로컬 관리자 화면의 Content Manager → Extra → チャーシュー에서 soldOut을 TRUE로 바꾸고 Publish → http://localhost:3000을 새로고침합니다(pnpm dev:web 실행 중).

6. 커밋 → PR → 머지

실행 위치: 저장소 루트 (DB 실행 중. 커밋할 때 타입 생성이 Strapi를 잠깐 띄운다)

git add apps
git commit -m "feat: 追加メニューに「売り切れ」表示を追加"
git push -u origin feat/extra-sold-out

커밋할 때 lefthook이 코드 모양 정리(와 gen-types를 넣었다면 타입 생성)를 해 줍니다. GitHub에서 PR을 만들면 CI 4개가 돌고, 모두 통과하면 squash 머지합니다.

7. 자동 배포 CI/CD

머지하면 06장의 배포가 스스로 시작합니다. 사람이 할 일은 없습니다.

단계이번 변경에서 일어나는 일
publishweb·cms 이미지를 새 커밋 번호로 빌드 → 검사 → 보관소(약 5분)
deployDB 등(Data)은 바뀐 것이 없어 그대로. 컨테이너만 새 이미지로 교체(약 5분)
ECS새 컨테이너가 뜬 뒤 옛 것을 내림(무중단). cms는 시작하면서 새 스키마를 보고 운영 DB에 soldOut 열을 추가

배포 직후 운영 사이트는 아무것도 바뀌지 않은 것처럼 보입니다. 운영 DB의 기존 데이터에는 품절 값이 비어 있기 때문입니다.

8. 운영에서 켜기 DB

운영 관리자 화면(06장의 AdminUrl)에서 로컬과 같은 조작을 합니다: Content Manager → Extra → チャーシュー → soldOut TRUE → Publish. 운영 사이트를 새로고침하면 1절의 "변경 후" 화면이 됩니다. 품절이 풀리면 FALSE로 되돌리면 되고, 이것은 배포 없이 바로 반영됩니다.

스키마는 배포되고, 데이터는 배포되지 않는다. 필드(그릇)는 코드로 운영에 갔지만, "무엇이 품절인가"(데이터)는 로컬에서 켜 둔 것이 운영으로 가지 않습니다. 날마다 바뀌는 것은 데이터로, 한 번 정하면 되는 표시 방법은 코드로 둡니다.

9. 커밋

feat: 追加メニューに「売り切れ」表示を追加 (#6)

이 장을 하면서 "타입 생성을 잊기 쉽다"는 것을 알게 되어, 커밋할 때 자동으로 만들도록 lefthook을 고쳤습니다(05장 4절의 gen-types).

chore: スキーマを変えたコミットでは型の再生成(gen:types)を自動で行う (#7)
