CHAPTER 04

Next.js 화면: 서버에서 안전하게 데이터 가져오기

03장에서 curl로 한 일을 Next.js 서버가 대신하게 만들고, 받아 온 데이터로 메뉴 페이지를 그립니다. 화면 디자인은 여러분의 사이트에 맞게 자유롭게 바꾸세요.

Next.js 서버가 토큰으로 Strapi의 데이터를 가져와 메뉴 페이지를 표시하고, 토큰이 브라우저에 전달되지 않는 것을 확인한다.

1. 구조: 누가 토큰을 쓰는가

Next.js의 서버 컴포넌트는 서버에서만 실행되는 React 컴포넌트입니다. App Router에서는 기본적으로 모든 컴포넌트가 서버 컴포넌트입니다. 여기서 토큰을 쓰면 브라우저에는 결과(HTML)만 전달되고, 토큰과 호출 코드는 전달되지 않습니다.

2. 패키지 설치

실행 위치: 저장소 루트

pnpm -F web add @strapi/client server-only
pnpm -F web add -D openapi-typescript
패키지역할
@strapi/clientStrapi 공식 JavaScript 클라이언트. populate 같은 조건을 객체로 쓰면 요청 URL을 대신 만들어 줍니다
server-only이 패키지를 import한 파일을 브라우저 쪽 코드에서 import하면 빌드 오류가 납니다. 토큰을 다루는 코드가 실수로 브라우저에 섞이는 것을 막습니다 (Next.js 문서)
openapi-typescriptAPI 명세(OpenAPI)에서 TypeScript 타입을 자동으로 만듭니다. 3절에서 사용합니다

3. 타입 자동 생성: CMS의 스키마를 프론트에서 다시 쓰지 않는다

프론트에서 데이터를 다루려면 "메뉴에는 name, sizes…가 있다"는 타입이 필요합니다. 이것을 손으로 쓰면 02장에서 만든 스키마를 한 번 더 적는 셈이고, 스키마를 바꿀 때마다 어긋날 위험이 있습니다. 그래서 Strapi의 스키마에서 자동으로 생성합니다.

명령을 등록합니다.

실행 위치: 저장소 루트

cd apps/cms && npm pkg set scripts.openapi="strapi openapi generate --output openapi.json" && cd ../..
cd apps/web && npm pkg set scripts.gen:types="openapi-typescript ../cms/openapi.json -o src/types/strapi.d.ts" && cd ../..
npm pkg set scripts.gen:types="pnpm -F cms openapi && pnpm -F web gen:types && biome format --write apps/web/src/types"

중간 파일인 openapi.json은 커밋하지 않으므로 .gitignore에 추가합니다.

# Strapi 가 생성하는 OpenAPI 명세 (타입 생성의 중간 산출물)
apps/cms/openapi.json

생성합니다. 02장에서 스키마를 바꿀 때마다 이 명령을 다시 실행합니다.

pnpm gen:types

생성된 strapi.d.ts 안에는 02장에서 화면으로 만든 스키마가 그대로 타입으로 들어 있습니다. 예를 들어 사이즈 부품은 이렇습니다.

    MenuSizeEntry: {
  /**
   * @description An enum field
   * @enum {string}
   */
  label: "small" | "medium" | "large";
  /** @description An integer field */
  noodleGrams?: number;
  /** @description An integer field */
  price: number;
};

Enumeration으로 만든 값이 "small" | "medium" | "large"로 들어 있습니다. 프론트에서 "smal"처럼 오타를 내면 에디터와 pnpm typecheck가 바로 알려 줍니다.

Strapi의 OpenAPI 생성 기능은 현재 실험적(experimental) 기능입니다(실행하면 경고가 표시됩니다). 앞으로 출력 형식이 바뀔 수 있습니다 (Strapi 문서: OpenAPI).

4. Strapi 접속: src/lib/strapi.ts

// Strapi 에 접속하는 클라이언트.
// "server-only": 이 파일을 브라우저 쪽 코드에서 import 하면 빌드 오류가 난다.
// → API 토큰이 브라우저로 보내는 JavaScript 에 섞여 들어가는 사고를 막는다.
import "server-only";
import { strapi } from "@strapi/client";

function requireEnv(name: string): string {
  const value = process.env[name];
  if (!value) {
    throw new Error(`환경변수 ${name} 가 설정되지 않았습니다`);
  }
  return value;
}

export function createStrapiClient() {
  return strapi({
    baseURL: `${requireEnv("STRAPI_URL")}/api`,
    auth: requireEnv("STRAPI_API_TOKEN"),
  });
}

// Strapi 의 이미지 URL 을 브라우저에서 표시할 수 있는 URL 로 만든다.
// 로컬에서는 "/uploads/xxx.png" 같은 상대 경로가 오므로 Strapi 주소를 붙인다.
// 운영(S3)에서는 처음부터 "https://..." 절대 URL 이 오므로 그대로 쓴다.
export function toPublicUrl(url: string): string {
  return url.startsWith("http") ? url : `${requireEnv("STRAPI_URL")}${url}`;
}
  • 토큰과 URL은 코드에 쓰지 않고 환경변수에서 읽습니다. 로컬은 .env.local(03장), 운영은 Secrets Manager에서 주입합니다(06장). 없으면 바로 오류를 내서 설정 실수를 빨리 알아차리게 합니다.
  • toPublicUrl: 로컬 Strapi는 사진 주소를 /uploads/…처럼 돌려주므로 Strapi 주소를 붙입니다.

5. 데이터 가져오기: src/lib/menu.ts

// 메뉴 페이지에 필요한 데이터를 Strapi 에서 가져온다.
import "server-only";
import { connection } from "next/server";
import { cache } from "react";
import type { components, paths } from "@/types/strapi";
import { createStrapiClient } from "./strapi";

// ---- 타입: Strapi 스키마에서 자동 생성된 것을 그대로 쓴다 (pnpm gen:types) ----
type Schemas = components["schemas"];
export type Menu = Schemas["ApiMenuMenuDocument"];
export type Topping = Schemas["ApiToppingToppingDocument"];
export type Extra = Schemas["ApiExtraExtraDocument"];
export type Media = Schemas["PluginUploadFileDocument"];
export type Shop =
  paths["/shop"]["get"]["responses"][200]["content"]["application/json"]["data"];

// ---- 조회 ----
// connection(): "빌드할 때가 아니라 요청이 올 때 실행하라"는 표시.
//   - 빌드(CI) 시점에는 Strapi 가 없어도 빌드가 성공한다
//   - 토큰·URL 을 실행 시점의 환경변수에서 읽으므로, 같은 이미지를 어느 환경에서든 쓸 수 있다
//   - 관리자 화면에서 Publish 하면 다음 요청부터 바로 반영된다
// cache: 한 요청 안에서 여러 번 불러도 Strapi 호출은 한 번으로 합친다
// (페이지 본문과 <title> 양쪽에서 가게 정보를 쓰기 때문)
export const getShop = cache(async () => {
  await connection();
  const res = await createStrapiClient()
    .single("shop")
    .find({ populate: ["photo"] });
  return res.data as Shop;
});

export async function getMenuPage() {
  await connection();
  const client = createStrapiClient();
  // API 4개를 동시에 호출한다 (하나씩 순서대로 부르는 것보다 빠르다)
  const [shop, menus, toppings, extras] = await Promise.all([
    getShop(),
    client.collection("menus").find({
      sort: "createdAt:asc",
      populate: {
        photo: true,
        sizes: true,
        toppings: { fields: ["name"] },
        extras: { fields: ["name"] },
      },
    }),
    client.collection("toppings").find({
      sort: "createdAt:asc",
      populate: { levels: true },
    }),
    client.collection("extras").find({
      sort: "createdAt:asc",
      populate: ["photo"],
    }),
  ]);
  return {
    shop,
    menus: menus.data as Menu[],
    toppings: toppings.data as Topping[],
    extras: extras.data as Extra[],
  };
}
포인트의미
populate03장의 ?populate=*와 같은 역할입니다. 사진·사이즈·토핑처럼 함께 가져올 것을 지정합니다
await connection()"빌드할 때가 아니라 손님이 페이지를 열 때 Strapi에 물어보라"는 표시입니다. 그래서 관리자 화면에서 Publish한 내용이 새로고침만으로 반영되고, 06장의 자동 빌드에서 Strapi가 없어도 빌드가 됩니다

그 밖의 Promise.all(여러 요청을 동시에 보내기)과 cache(같은 요청을 한 번으로 합치기)는 속도를 위한 것이라, 몰라도 동작을 이해하는 데 지장은 없습니다.

6. 화면: 받아 온 값을 화면에 넣는다

여기가 이 장의 핵심입니다. "Strapi에서 받아 온 값이 화면의 어디에 나오는가"만 따라가 봅니다.

아래 코드는 이해하기 쉽도록 디자인 설정(className 등)을 뺀 요약입니다. 실제 page.tsx에는 디자인 설정이 들어 있습니다. 디자인은 여러분의 사이트에 맞게 자유롭게 만들면 되고, 여러분의 화면이 이 자료와 달라도 괜찮습니다.

① 데이터를 받는다

export default async function Page() {
  const { shop, menus, toppings, extras } = await getMenuPage();
  ...
}

이 한 줄에서 Next.js 서버가 토큰을 붙여 Strapi에 요청합니다(03장의 curl과 같은 일). 결과는 네 개의 상자에 담깁니다.

상자들어 있는 것
shop가게 정보 1건 (Single Type)
menus메뉴 목록 (ラーメン, つけ麺)
toppings무료 토핑 목록
extras추가 메뉴 목록

이제 이 값을 HTML 안의 { } 자리에 넣으면 화면이 됩니다.

② 가게 이름

<h1>{shop.name}</h1>
<p>{shop.catchphrase}</p>

③ 메뉴 카드

{menus.map((menu) => (          // 메뉴 수만큼 아래를 반복
  <article>
    <Photo media={menu.photo} />   // 사진
    <h3>{menu.name}</h3>           // ラーメン
    <p>{menu.description}</p>      // 설명
    {menu.sizes.map((size) => (   // 사이즈 수만큼 반복
      <tr>
        <th>{SIZE_LABEL[size.label]}</th>   // small → 小
        <td>麺 {size.noodleGrams}g</td>
        <td>{yen(size.price)}</td>          // 800 → 800円
      </tr>
    ))}
  </article>
))}

SIZE_LABEL은 02장에서 small처럼 영어로 저장한 값을 화면용 글자 「小」로 바꾸는 표입니다.

const SIZE_LABEL = { small: "小", medium: "中", large: "大" };

④ 나머지 부분

같은 방식으로 값을 넣습니다.

화면코드에서 넣는 값
무료 토핑topping.name, topping.description, 그리고 topping.levels의 label(ナシ〜マシマシ)을 반복
추가 메뉴extra.photo, extra.name, extra.price
가게 정보shop.address, shop.businessHours, shop.closedDays, shop.ticketRule

8. 토큰이 브라우저에 없는지 확인

이 장의 핵심입니다. 브라우저의 개발자도구로 직접 확인합니다.

  1. 개발자도구(F12) → Network 탭을 열고 페이지를 새로고침합니다. 요청 목록에 localhost:1337/api가 하나도 없습니다. 브라우저는 Strapi API를 직접 부르지 않고, 사진(/uploads/…)만 받아 옵니다.
  2. 페이지 소스 보기(Ctrl+U / ⌘+Option+U)에서 토큰의 앞부분을 검색합니다. 찾을 수 없습니다.
만약 토큰을 NEXT_PUBLIC_ 변수로 만들었거나, 브라우저 쪽 코드("use client")에서 Strapi를 호출했다면?

토큰이 브라우저로 보내는 JavaScript에 포함되고, Network 탭에 Strapi 호출이 그대로 보입니다. 누구나 토큰을 복사해서 API를 쓸 수 있게 됩니다. server-only를 넣어 두었기 때문에, lib/strapi.ts를 브라우저 쪽 코드에서 import하면 빌드 단계에서 오류가 나서 이런 실수를 막을 수 있습니다.
