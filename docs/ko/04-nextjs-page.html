Next.js 서버가 토큰으로 Strapi의 데이터를 가져와 메뉴 페이지를 표시하고, 토큰이 브라우저에 전달되지 않는 것을 확인한다.

1. 구조: 토큰은 서버에만

Next.js의 서버 컴포넌트는 서버에서만 실행되는 화면 코드입니다(App Router에서는 기본값). 여기서 토큰을 쓰면 브라우저에는 완성된 HTML만 가고, 토큰과 호출 코드는 가지 않습니다. 00장 비유의 "홀 직원만 출입증을 가진다"가 이것입니다.

2. 필요한 패키지

실행 위치: 저장소 루트

pnpm -F web add @strapi/client server-only
pnpm -F web add -D openapi-typescript
패키지역할
@strapi/clientStrapi 공식 클라이언트. "사진도 함께" 같은 조건을 쓰면 요청 주소를 만들어 준다
server-only이것을 넣은 파일을 브라우저용 코드에서 쓰면 빌드 오류 → 토큰이 실수로 브라우저에 섞이는 것을 막는다
openapi-typescript3절의 타입 자동 생성에 쓴다

3. 타입 자동 생성: 스키마를 다시 쓰지 않는다

화면 코드가 "메뉴에는 name, sizes…가 있다"를 알면, 오타를 에디터가 바로 알려 줍니다. 이 정보(타입)를 손으로 쓰면 02장의 스키마를 한 번 더 적는 셈이므로, 스키마에서 자동으로 만듭니다.

예를 들어 02장에서 선택지로 만든 사이즈는 "small" | "medium" | "large"라는 타입이 됩니다. 화면 코드에서 "smal"이라고 잘못 쓰면 바로 오류로 알려 줍니다.

이 명령은 처음에 직접 등록합니다(저장소에는 이미 있음).

실행 위치: 저장소 루트

cd apps/cms && npm pkg set scripts.openapi="strapi openapi generate --output openapi.json" && cd ../..
cd apps/web && npm pkg set scripts.gen:types="openapi-typescript ../cms/openapi.json -o src/types/strapi.d.ts" && cd ../..
npm pkg set scripts.gen:types="pnpm -F cms openapi && pnpm -F web gen:types && biome format --write apps/web/src/types"

중간 파일 apps/cms/openapi.json은 .gitignore에 넣어 커밋하지 않습니다. Strapi의 OpenAPI 생성은 현재 실험적(experimental) 기능이라 출력 형식이 바뀔 수 있습니다.

등록했으면 실행합니다.

실행 위치: 저장소 루트 (DB 실행 중)

pnpm gen:types

4. Strapi 접속과 데이터 가져오기

코드는 두 파일로 나눴습니다. 핵심만 보면 이렇습니다.

apps/web/src/lib/strapi.ts

Strapi에 접속하는 준비. URL과 토큰은 환경변수에서 읽는다(로컬은 .env.local, 운영은 AWS가 넣어 줌). 없으면 바로 오류를 내서 설정 실수를 빨리 알 수 있다

apps/web/src/lib/menu.ts

메뉴 페이지에 필요한 데이터를 한 번에 가져온다. 사진·사이즈·토핑처럼 함께 가져올 것(03장의 populate)을 여기서 지정한다

apps/web/src/lib/strapi.ts

import "server-only";
import { strapi } from "@strapi/client";

function requireEnv(name: string): string {
  const value = process.env[name];
  if (!value) {
    throw new Error(`환경변수 ${name} 가 설정되지 않았습니다`);
  }
  return value;
}

export function createStrapiClient() {
  return strapi({
    baseURL: `${requireEnv("STRAPI_URL")}/api`,
    auth: requireEnv("STRAPI_API_TOKEN"),
  });
}
"요청이 올 때마다 조회"하는 이유 (connection()) 생략 가능

menu.ts는 조회 전에 await connection()을 부릅니다. "빌드할 때가 아니라 손님이 페이지를 열 때 Strapi에 물어보라"는 표시입니다. 그래서 ① 관리자 화면에서 Publish한 내용이 새로고침만으로 반영되고, ② 자동 빌드(05·06장)에서 Strapi가 없어도 빌드가 되며, ③ 같은 이미지를 로컬·운영 어디서든 쓸 수 있습니다.

5. 화면: 받아 온 값을 어디에 넣나

이 장의 핵심입니다. "Strapi에서 받은 값이 화면의 어디에 나오는가"만 따라갑니다. 아래는 디자인 설정을 뺀 요약이고, 실제 파일은 apps/web/src/app/page.tsx입니다.

const { shop, menus, toppings, extras } = await getMenuPage();   // 서버가 토큰으로 조회

<h1>{shop.name}</h1>                 // 가게 이름
{menus.map((menu) => (                 // 메뉴 수만큼 카드를 반복
  <article>
    <h3>{menu.name}</h3>
    {menu.sizes.map((size) => (         // 사이즈 수만큼 줄을 반복
      <tr><th>{SIZE_LABEL[size.label]}</th><td>{yen(size.price)}</td></tr>   // small → 小, 800 → 800円
    ))}
  </article>
))}

토핑·추가 메뉴·가게 정보도 같은 방식으로 값을 넣습니다.

6. 확인: 토큰이 브라우저에 없다

실행 위치: 저장소 루트 (터미널 3개)

pnpm dev:db
pnpm dev:cms
pnpm dev:web   # → http://localhost:3000
  1. 관리자 화면에서 가격을 바꾸고 Publish → 새로고침하면 바로 반영됩니다.
  2. 브라우저 개발자도구(F12) → Network 탭: localhost:1337/api 요청이 하나도 없습니다. 브라우저는 사진만 받아 옵니다.
  3. 페이지 소스 보기에서 토큰의 앞부분을 검색해도 찾을 수 없습니다.

7. 검사·빌드·커밋

실행 위치: 저장소 루트

pnpm format && pnpm lint && pnpm typecheck
pnpm -F web build
git add .
git commit -m "feat(web): メニューページ"

빌드 결과에서 /가 ƒ (Dynamic)으로 표시됩니다. "요청이 올 때 서버에서 만든다"는 뜻이라, 빌드할 때 Strapi가 없어도 됩니다.
