店の情報・メニュー・サイズ・トッピング・追加メニューを Strapi のスキーマとして作り、画面での操作がファイルとして保存されることを確認する。

1. まず「何を見せるか」を書き出す

皆さんのサイトに置き換えて、同じ順序で考えてみてください。この例のメニューページには、こんな情報が必要です。

  • 店名、住所、営業時間、定休日、食券のルール、店の写真
  • メニュー(ラーメン、つけ麺)とサイズ(小/中/大)ごとの麺の量・価格
  • 無料トッピング(ニンニク・ヤサイ…)と選べる量(ナシ〜マシマシ)
  • 有料の追加(ライス、チャーシュー)と価格

2. Strapi の「入れ物」4種類

お店の前にあるメニュー表を思い浮かべてください。メニュー表の情報は性質によって4種類の入れ物に分かれます。

入れ物メニュー表では一言で
① Single Type一番上の店名・営業時間1つしかない情報
② Collection Typeラーメンのカード、つけ麺のカード…同じ形で複数
③ Componentカードの中の「小 800円 / 中 900円」どこかに付いている部品
④ Relationメニューと追加メニュー・トッピングをつなぐ線別に用意して線でつなぐ
選ぶ基準は3つの質問です。1つしかないか? → Single Type。複数を一覧で管理するか? → Collection Type。どこかに付いているか、複数箇所で共有するか? → 付いていれば Component、共有するなら Collection として別に作り Relation でつなぐ。
なぜサイズは部品で、追加メニューは線(Relation)なのですか? 省略可

ラーメンの小は800円、つけ麺の小は900円のように、サイズの価格はメニューごとに違うので共有するものがありません → 各カードに付く部品にします。逆に「ライス ＋100円」はどのメニューに付いても同じです。1か所に書いて線でつなげば、値上げのときも1か所直すだけで済みます。

皆さんのサイトならSingleCollectionComponentRelation
会社のホームページ会社紹介お知らせ、社員社員の SNS リンクお知らせ → 書いた社員
ブログブログ紹介記事、タグ記事内の関連リンク記事 ↔ タグ

3. 管理画面で作る

実行場所: リポジトリのルート

pnpm dev:db
pnpm dev:cms   # → http://localhost:1337/admin

初回アクセスで管理者登録画面が出ます(ローカル専用アカウント)。登録後、左メニューのContent-Type Builderで入れ物を作り、フィールドを追加します。

今回作った入れ物とフィールドです。必須かどうかなどは、フィールドのADVANCED SETTINGSで決めます。

入れ物フィールド
Single Shopname(必須), catchphrase, address, closedDays, businessHours・ticketRule(複数行), photo(写真)
Component menu.sizelabel(small / medium / large から選択、必須), noodleGrams, price(必須)
Component menu.levellabel(ナシ・フツウ… 必須)
Collection Toppingname(必須), description, levels(menu.level を複数)
Collection Extraname(必須), price(必須), photo (07章で soldOut を追加)
Collection Menuname(必須), description, photo, sizes(menu.size を複数), extras・toppings(多対多 Relation)

迷いやすい点

① 選択肢(Enumeration)の値は英字で。 小をそのまま入れるとエラーになります。値はプログラムが使う識別子で、「小」という表示は画面(04章)側で付けます。

② 部品を複数付けるには Repeatable。 メニュー1つにサイズ3個、トッピング1つに量4個。

③ 線(Relation)の種類は文章で確認。 アイコンを選ぶと、下に意味が文章で表示されます。

Content-Type Builder はローカル(開発モード)でしか使えません。本番ではロックされています。スキーマはローカルで変更し、Git でデプロイします。

4. 保存すると「ファイル」になる

左上のSaveを押すと、Strapi が再起動しながら設計図ファイルを書き込みます。

apps/cms/src/api/<入れ物>/content-types/<入れ物>/schema.json

入れ物の設計図。画面で選んだフィールドがそのまま書かれる

apps/cms/src/api/<入れ物>/controllers・routes・services

API を作るコード。自動生成なので手を加えない

apps/cms/src/components/menu/*.json

部品(Component)の設計図

schema.json の中身を見る 省略可

apps/cms/src/api/menu/content-types/menu/schema.json

"sizes": {
  "type": "component",
  "component": "menu.size",
  "repeatable": true
},
"extras": {
  "type": "relation",
  "relation": "manyToMany",
  "target": "api::extra.extra",
  "inversedBy": "menus"
},
"toppings": {
  "type": "relation",
  "relation": "manyToMany",
  "target": "api::topping.topping",
  "inversedBy": "menus"
}

画面で選んだ「部品を複数」「多対多の線」が、そのまま JSON に書かれています。

この研修の要点の1つ。この設計図ファイル(スキーマ)は Git → PR → 自動デプロイを経て本番に行き、本番の Strapi が起動するときにテーブルを作ります。しかし管理画面で入力したデータは、それぞれの環境の DB にしかなく、デプロイされません。

5. コミット

実行場所: リポジトリのルート

git add .
git commit -m "feat(cms): メニューのスキーマを追加"
