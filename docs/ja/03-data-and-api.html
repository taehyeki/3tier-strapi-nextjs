管理画面でデータを入力・公開し、API トークンを発行して curl でメニューデータを取り出してみる。

1. データの入力と公開

左メニューのContent Managerで、入れ物ごとにデータを入力します。つながる側を先に作ります: Topping・Extra を作ってから、Menu でそれらを選びます。

入力する場所この資料の例
Shop麺屋ヤマモリ、一言紹介、住所・営業時間・定休日・食券のルール、店の写真
Topping ×4ニンニク・ヤサイ・アブラ・カラメ(量: ナシ / フツウ / マシ / マシマシ)
Extra ×2ライス 100、チャーシュー 200(写真つき)
Menu ×2ラーメン、つけ麺(サイズごとの麺の量・価格、つなげるトッピング・追加メニュー)
Save と Publish は違います。Save は下書き保存なので外には出ません。Publishを押して初めて API から出ます(= サイトに表示)。「保存したのにサイトに出ません」の原因は、たいてい Publish していないことです。
ここで入力したデータはこの PC の DB だけにあります。Git にも入らず、本番にデプロイもされません。本番では本番の管理画面で改めて入力します(06章)。

2. API: バックエンドの「注文窓口」

Strapi は入力したデータを自動的にAPI(プログラムがデータを受け取る窓口)として提供します。アドレスは /api/複数形の名前 です。まずそのまま呼んでみます。

実行場所: どこでも(Strapi 実行中)

curl http://localhost:1337/api/menus
{"data":null,"error":{"status":403,"name":"ForbiddenError","message":"Forbidden",...}}

403(権限なし)が正常です。Strapi の API は最初、すべて鍵がかかっています。開ける方法は2つあります。

方法誰が読めるか今回の選択
Public ロールに権限を付与インターネットの誰でも
API トークントークン(通行証)を持つ側だけ✔ Next.js サーバーだけが持つ
API トークンは厨房窓口の通行証です。通行証をホールスタッフ(Next.js サーバー)だけが持っていれば、お客様(ブラウザ)は窓口に直接来られず、必ずホールスタッフを通します。

3. API トークンの発行

Settings → API Tokens → Create new API Token。

項目値理由
Nameweb (local)誰が使う通行証かわかるように
Token typeCustom必要な権限だけ選ぶため
PermissionsMenu・Topping・Extra: find findOne / Shop: find読み取りだけ。作成・更新・削除は許可しない

Save を押すとトークンが表示されます。パスワードと同じなので、チャットや Git には貼り付けません。

「Read-only」ではなく「Custom」を選ぶ理由 省略可

Read-only は会員情報などすべてのデータを読めます。Custom で画面に必要なものだけ許可すれば、トークンが漏れてもメニュー情報を読まれる程度で済みます(最小権限)。

4. トークンを付けて再リクエスト

実行場所: どこでも(Strapi 実行中)

TOKEN=コピーしたトークン
curl -H "Authorization: Bearer $TOKEN" "http://localhost:1337/api/menus?populate=*"
{ "data": [ { "name": "ラーメン", "sizes": [ { "label": "small", "price": 800 }, … ], … }, … ] }

403 の代わりに、入力したメニューが JSON で返ってきます。

送ったもの結果意味
トークンなし403誰かわからないので拒否
間違ったトークン401通行証が偽物
正しいトークン200 + データ通行証も本物、権限もある
正しいトークンで権限外(例: /api/users)403通行証は本物だがその扉は開けられない
?populate=* とは何ですか? 省略可

Strapi は既定で文字・数値のフィールドしか返しません。写真・部品・つながり(Relation)は「一緒に持ってきて」と指定しないと含まれません。populate=* は「1段階下まですべて含める」という意味です。

5. トークンを Next.js 側に置く

いま curl でやったことを、04章からは Next.js サーバーが行います。そのためトークンは apps/web の環境変数ファイルに置きます。

apps/web/.env.local

本物のトークンを入れる。Git には上げない

apps/web/.env.example

「STRAPI_URL と STRAPI_API_TOKEN が必要」とだけ書いた例。Git に上げる

実行場所: リポジトリのルート

cp apps/web/.env.example apps/web/.env.local
# apps/web/.env.local を開き、STRAPI_API_TOKEN= の後ろにトークンを貼り付ける
変数名の前に NEXT_PUBLIC_ を付けてはいけません。付けると、値がブラウザに送られるコードに混ざり、誰でも見られるようになります。また create-next-app が作る apps/web/.gitignore は .env* をすべて無視するので、末尾に !.env.example を足して例のファイルだけコミットされるようにします。

git status        # .env.local が一覧にないか確認
