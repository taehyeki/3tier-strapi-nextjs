1. 今回の研修でやること

皆さんはすでに3層アーキテクチャ(Web → アプリ → DB)のインフラを設計しました。今回はその上に載るアプリケーションを自分で作り、GitHub を通して自動でデプロイする流れを体験します。

例として、キム系ラーメン店「麺屋ヤマモリ」のメニューサイトを作ります。店のスタッフが管理画面でメニューと価格を入力すると、お客様が見るサイトにそのまま反映されます。

この資料は正解ではなく参考例です。コードはリポジトリにすべてあるので、資料では流れと要点だけを読み、皆さんが作りたいサイト(テーマ・データ・画面)に置き換えて作ってみてください。ラーメン店のデータや写真は提供しません。省略可と付いた部分は、知らなくても先に進める補足説明です。

2. 3層構成をお店にたとえると

Web サービスは大きく3つの部分に分かれます。ラーメン店にたとえるとこうなります。

フロントエンドホール(お客様が見る場所)お客様に見せる画面を作る今回の例: Next.js
→
バックエンド厨房 + 注文窓口データを管理し、決まった窓口(API)から渡す今回の例: Strapi
→
DB食材倉庫データを長期保管する今回の例: PostgreSQL
ホールのスタッフ(フロントエンド)は倉庫(DB)に直接入りません。厨房の窓口(API)に「メニュー一覧をください」と注文し、受け取ったものをお客様の前にきれいに並べます。窓口は通行証(API トークン)を持つスタッフの注文だけを受け付けます。

WordPress ではこの3つが1つの塊でした。今回は画面(Next.js)と管理ツール・API(Strapi)を分けて、両者がどう通信するかを自分の手で作ります。

Strapi は「ヘッドレス CMS」と呼ばれる種類のツールです。データの入れ物(スキーマ)を管理画面でクリックして作るだけで、そのデータを出し入れする API が自動でできます。バックエンドを1からコードで書かなくても、自分だけの CMS(コンテンツ管理の仕組み)を簡単に組み立てられるというのがポイントです。Next.js はその API から受け取ったデータを画面にする、React ベースの Web フレームワークです。
なぜアプリを2つに分けるのですか? 省略可
  • 役割分離: 画面のデザインを変えても CMS はそのまま、CMS を更新しても画面はそのままにできます。
  • セキュリティ: API トークンを Next.js サーバーの中だけに置けば、ブラウザからは絶対に見えません。
  • 再利用: 同じ API をスマートフォンアプリや他のサイトでも使えます。この構造をヘッドレス CMSと呼びます。

3. 完成した姿(AWS)

層役割今回の構成
1層 Webリクエストを受ける入口CloudFront + ALB
2層 アプリ画面を作り、データを処理フロント Next.js ・ バックエンド Strapi
3層 データデータとファイルを保存DB Aurora PostgreSQL + S3(写真)

4. 自分の PC の開発環境

開発は自分の PC で行います。AWS と同じ3層構造を、PC の中に小さく再現します。

5. 開発からデプロイまで

① ローカルで開発自分の PC で作って確認01〜04章
→
② PR「この変更を反映してください」CI が自動検査 ・ 05章
→
③ マージ検査を通過したら main に取り込む05章
→
④ 自動デプロイmain が変わると AWS に反映CD ・ 06章

人がやるのは①〜③だけです。AWS のコンソールを触らなくても本番まで反映されます(本番データの入力だけは本番の管理画面で行います。07章で実際にやってみます)。

6. コードでやること、管理画面でやること

Strapi を使うと、最初に基本設定だけコードでしておけば、あとのデータ作業は管理画面で完結します。

コードでやること

・リポジトリの骨組み、DB コンテナ(01章)
・画面(Next.js)(04章)
・自動検査・デプロイの設定(05・06章)
・本番用の設定、AWS 構成(06章)

Strapi の管理画面でやること

・データ構造(スキーマ)の設計。ローカルだけ(02章)
・データの入力・修正・公開(03章)
・API トークンの発行(03章)
・写真のアップロード

管理画面で作ったデータ構造は、Strapi が設計図ファイル(schema.json)として自動保存し、このファイルはコードと同じように Git で本番にデプロイされます。一方、入力したデータはデプロイされません。本番では本番の管理画面で入力します。

7. 使う道具

フロント Next.js

React ベースの Web フレームワーク。サーバーで HTML を作れるので、トークンのような秘密をサーバーだけに置けます。

バックエンド Strapi

オープンソースのヘッドレス CMS。管理画面でデータ構造を作ると API が自動でできます。

DB PostgreSQL

リレーショナル DB。ローカルでは Docker で、AWS では Aurora で動かします。

Docker

プログラムを「コンテナ」という箱に入れて、どこでも同じように動かします。

pnpm ・ Biome

パッケージ管理(複数のアプリを1つのリポジトリで) ・ コードの形の統一とミスの検出。

CI/CD GitHub Actions ・ AWS CDK

自動検査・自動デプロイ ・ AWS の構成をコードで書く道具。
