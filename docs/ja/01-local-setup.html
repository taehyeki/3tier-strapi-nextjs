http://localhost:3000(画面)と http://localhost:1337/admin(CMS 管理画面)が開き、CMS が DB に接続された状態を作る。

1. 何を作るか

3つを1つのリポジトリ(フォルダ)にまとめます。この構成をモノレポと呼びます。「CMS のデータ構造変更 + 画面変更」を一度に検査・デプロイできて便利です。

📁 この章が終わると
3tier-strapi-nextjs/
├── apps/
│   ├── web/      フロント Next.js  (create-next-app が生成)
│   └── cms/      バックエンド Strapi   (create-strapi が生成)
├── compose.yaml  DB    PostgreSQL コンテナの設定
└── 設定ファイルいくつか(バージョン固定、コマンド集、コード検査のルール)

3. リポジトリの骨組み

実行場所: 作業用フォルダ

mkdir 3tier-strapi-nextjs && cd 3tier-strapi-nextjs
git init -b main
mkdir apps

ルートに設定ファイルを置きます。内容はリポジトリのファイルを参照してください。リポジトリのファイルは最後の章まで終わった状態なので、あとの章で追加した行(lefthook、型生成コマンド、infra、脆弱性対応の overrides)も入っています。この章の時点の姿は、01章のコミットで確認できます。

package.json

よく使うコマンド集(pnpm dev:cms など)と pnpm バージョンの固定

pnpm-workspace.yaml

apps/ 配下のアプリを1つにまとめる + インストール時のセキュリティ設定

.nvmrc

Node バージョンの固定(24)。全員が同じバージョンを使う

.gitignore

Git に上げないもの: 秘密の値(.env)、インストール結果など

.editorconfig 省略可

エディタが違っても、インデント・改行を揃える

pnpm が防いでくれる2つのこと(サプライチェーン攻撃対策) 省略可

誰かが有名なパッケージに悪意あるコードを混ぜて公開する攻撃(サプライチェーン攻撃)は実際に起きています。pnpm 12 は既定で、①インストール時にパッケージのスクリプト実行を禁止し(許可したものだけ pnpm-workspace.yaml の allowBuilds に書く)、②公開されてから1日経っていないバージョンはインストールしません。新しいパッケージを入れて ERR_PNPM_IGNORED_BUILDS が出たら、allowBuilds にそのパッケージを書いて許可するか決めます。

4. DB: コンテナで立てる DB

DB は PC にインストールせず、Docker コンテナで動かします。誰の PC でも同じバージョンが立ち上がり、不要になれば丸ごと消せます。設定は compose.yaml の1つだけです。

設定値意味
イメージpostgres:17-alpine本番(Aurora)と同じメジャーバージョン
DB 名・ユーザー・パスワードすべて strapiローカル専用の値。本番のパスワードは AWS がランダムに作る(06章)
ポート5432PC からこの番号で接続
ボリュームdb-dataコンテナを消してもデータが残る

実行場所: リポジトリのルート

pnpm dev:db
docker compose ps

STATUS に (healthy) と表示されます。

5. CMS: Strapi のインストール バックエンド

実行場所: リポジトリのルート

npx create-strapi@latest apps/cms \
  --ts --use-pnpm --install --no-run --skip-cloud --no-example --no-git-init \
  --dbclient postgres --dbhost 127.0.0.1 --dbport 5432 \
  --dbname strapi --dbusername strapi --dbpassword strapi --dbssl false

TypeScript で、サンプルデータなしで、4節の DB に接続するように作ります。続けてモノレポに合わせて少し整理します。

実行場所: apps/cms

# Strapi Cloud(有料ホスティング)用なので不要(この2行は省略しても動きます)
pnpm remove @strapi/plugin-cloud
npm pkg delete scripts.deploy scripts.upgrade "scripts.upgrade:dry"
# pnpm の設定はルート1か所にまとめる
npm pkg delete pnpm
# 型検査コマンド(05章の自動検査が使う)
npm pkg set scripts.typecheck="tsc --noEmit"
pnpm add -D @types/node@^24

設定値は「環境変数」で受け取る

Strapi の設定ファイルは、DB のアドレスや秘密の値を直接書かず、環境変数という名札で読みます(例: DATABASE_HOST)。値を入れる場所だけが環境ごとに違います。

ローカルapps/cms/.env ファイル生成ツールが作る。秘密の値が入っているので Git には上げない
→
同じ名前で読むenv("DATABASE_HOST")コードはローカル・本番とも同じ
←
本番(AWS)Secrets Manager などECS がコンテナに渡す(06章)

代わりに「どんな値が必要か」だけを書いた apps/cms/.env.example を Git に上げます(値はダミー)。

それぞれの秘密の値は何に使われますか? 省略可
変数使われる場所値が変わると
APP_KEYSログインセッションに署名(改ざん防止の印)ログインセッションが無効に
ADMIN_JWT_SECRET管理者ログイントークンに署名管理者が再ログイン
API_TOKEN_SALTAPI トークン(03章)を保存するときに混ぜる値発行した API トークンがすべて無効に
ENCRYPTION_KEY発行したトークンを管理画面で再表示できるよう暗号化保存されたトークンを表示できなくなる
TRANSFER_TOKEN_SALT, JWT_SECRET今回は使わない機能用—

実行場所: リポジトリのルート

pnpm install
pnpm dev:cms

http://localhost:1337/admin で管理者登録画面が開きます(登録は02章で)。

6. 画面: Next.js のインストール フロント

実行場所: リポジトリのルート

npx create-next-app@latest apps/web \
  --ts --tailwind --biome --app --src-dir --import-alias '@/*' \
  --use-pnpm --skip-install --disable-git

重要なのは --app(App Router)です。サーバーでしか実行されないコードを書けるので、04章で API トークンをブラウザから隠せます。続けてモノレポに合わせて整理します。

実行場所: リポジトリのルート

rm apps/web/pnpm-workspace.yaml     # pnpm の設定はルート1か所に
mv apps/web/biome.json biome.json   # コード検査のルールをルートに移し web・cms 共通に
cd apps/web
npm pkg delete packageManager scripts.lint scripts.format "devDependencies.@biomejs/biome"
npm pkg set scripts.typecheck="next typegen && tsc --noEmit"
cd ../..
pnpm add -D @types/node@^24 --filter web
pnpm install
pnpm dev:web

7. コード検査ツール(Biome)と最初のコミット

Biome はコードの形を統一(フォーマット)し、よくあるミスを見つけ(リント)ます。ルートの biome.json 1つで、すべてのアプリに同じルールを適用します。ルールは既定の推奨セット(recommended)を使い、自動生成ファイル・ドキュメントなどは検査から外します。全体: biome.json

実行場所: リポジトリのルート

pnpm install
pnpm format      # 全コードをルールに合わせて自動修正
pnpm lint        # 検査のみ
git add .
git commit -m "chore: ローカル開発環境を構築"

Strapi が作ったファイルで警告(warning)がいくつか出ますが、生成ツールのコードスタイルによるものなので問題ありません。error がなければ大丈夫です。

コミットメッセージのルール 省略可

種類: 内容 の形式(Conventional Commits)で書きます。種類は feat(機能)、fix(修正)、chore(設定)、docs(ドキュメント)くらいで十分です。内容はチームが読む言語で書きます(この例では日本語)。
